## DEC-ENG-001｜strategy-agnostic system infrastructure

| 字段 | 记录 |
| --- | --- |
| decision_id | DEC-ENG-001 |
| decision | 允许建设战略无关系统骨架，但不因此锁定任何业务战略。 |
| decided_by | user |
| decision_date | 2026-08-19 |
| input_evidence | 用户本轮明确授权的主体系统开发 prompt 与治理补充 prompt；已回读当前 `strategy_definition_pending`、脚本边界和医疗安全机制。 |
| alternatives_considered | 继续等待业务战略锁定后再建设；直接建设依赖特定国家、产品或平台的自动化。 |
| why_selected | 先建立可配置、可审计、可用模拟数据验证的通用容器，避免未来业务事实变化时重写核心领域代码。 |
| scope | 仅限系统架构、数据结构、内部流程、模拟数据、测试、dry-run（模拟运行）和外部适配器接口。 |
| success_condition | 业务事实、国家、产品、价格、渠道、医院发生改变时，不需要修改核心领域代码。 |
| failure_condition | 核心代码出现业务战略硬编码，或系统开发反向形成业务 Decision（正式决策）。 |
| revisit_trigger | 系统架构被现实业务验证证明不适用，或新增医疗、法律、数据专业约束。 |
| supersedes | 无；本决定仅精化此前的“暂不放业务自动化脚本”边界。 |
| status | locked |

**边界说明：** 此记录是 `engineering_scope_decision`，不是市场、客户、产品、价格、医院、渠道、商业模式、Supply First / Demand First 或 Go / No-Go 的业务战略决定。真实外部动作继续默认关闭。
