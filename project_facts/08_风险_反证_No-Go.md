# 风险、反证与 No-Go

## 当前最大风险

项目最容易犯的错误是将资源、公开介绍、口头兴趣和宏观需求误读为可出售、可交付、可盈利且合规的跨境服务。当前风险控制的重点不是写得更完整，而是尽早得到反证。

## No-Go 触发器

| 触发器 | 需要的反证/证据 | 当前处理 |
| --- | --- | --- |
| 拿不到书面机构价格、外籍流程、双语交付或异常/转诊 SLA | 机构书面回复和核验表 | 停止对外报价，回到 Supply |
| 法律意见否定当前三账或数据/广告/合同结构 | 专业书面意见 | 停止相关结构，重做或终止 |
| 目标用户不愿付订金 | 有渠道归因的报价和订金记录 | 停止把兴趣当需求，重判产品/市场 |
| CAC 长期超过模型 | 实际渠道账单与归因 | 暂停该渠道，不扩大支出 |
| 无法获得 3 单真实成行 | 订金、取消、旅行和完成记录 | 不宣布 Delivery 成立 |
| P50 贡献为负或明显低于门槛 | 完整成本、退款和收入账 | 不扩张，重审价格/成本/范围 |
| 退款、取消或投诉不可控 | 异常日志与合同/流程证据 | 暂停收款，修复或终止 |
| 重大医疗责任越界 | 事件记录、机构/专业方复盘 | 立即停止相关服务，按责任路径处理 |
| 重大数据事件 | 事故记录、访问/传输证据 | 停止数据流程，按专业事故响应处理 |
| 必须靠疗效承诺才能成交 | 销售话术/客户反馈/审核证据 | 终止该产品表达，不以误导换转化 |

## 风险登记口径

每个风险/事件写入 review_loop/incident_and_boundary_log.md，至少记录：

- 去标识化 case_id 或聚合范围。
- 发现日期、触发方式、严重度、事实/推断区分。
- 临时控制、责任主体、是否需要用户/专业方决策。
- 修复层：目标、机制、设计、执行、材料/证据或验收。
- 验证结果与是否影响项目状态。

## 停止不是失败掩盖

若 No-Go 触发，正式动作是：停止受影响路径、保留可审计的匿名化证据、明确哪项假设被反证、避免转移到未验证的新国家/新产品逃避结论。只有用户作出新的范围决定或新可信事实出现，才可开启新验证轮。
