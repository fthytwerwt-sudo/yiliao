# 协作操作系统总览

本目录是成都国际医疗旅游项目的 canonical collaboration system。它只定义用户、ChatGPT、Codex、GitHub、Project、本地执行现场、Obsidian 和外部研究工具怎样协作；不定义当前首发国家、产品、价格、渠道、商业模型、供应商、Go/No-Go 或验证顺序。

## 解决什么问题

这个机制解决长期项目里最容易发生的四类错位：

| 错位 | 正确处理 |
| --- | --- |
| 聊天里说过，就以为仓库已知道 | 只有写入 GitHub main 并远端回读后，才是跨会话项目事实 |
| 研究资料很完整，就以为战略已锁定 | 研究只能是 candidate / inference / hypothesis，不能自动成为 Decision |
| Codex 能写文件，就以为它能决定方向 | Codex 执行已锁定设计，不决定市场、客户、产品、价格或 Go/No-Go |
| 文件存在、测试通过，就以为任务完成 | 需要分清技术、内容、人工、业务和同步完成态 |

## 信息流

用户提出目标或纠正 → ChatGPT 回读 GitHub main 当前事实 → 触发真实意图、事实源和任务路由判断 → 用户与 ChatGPT 锁定目标、边界、验收、Implementation Design → Codex 按执行合同写入、验证和回写 → Completion Relay Gate 检查剩余工作 → Git commit/push/readback → ChatGPT 复审完成态 → 必要时更新 Project 静态包或 Obsidian 机制库。

任何环节发现目标未锁、事实冲突、权限不足、医疗专业风险或外部动作未授权，都先 blocked，而不是用“看起来合理”的路线填空。

## 四层物理职责

| 层 | 保存什么 | 不保存什么 | 什么时候更新 |
| --- | --- | --- | --- |
| ChatGPT Project | 项目指令、协作机制静态包、用户希望聊天持续参考的少量资料 | 当前动态事实、密钥、患者/个人健康信息、每条日志、业务状态 | 协作机制变化或用户要求刷新 Project 时，由用户人工上传 |
| GitHub main | 动态项目事实、正式决策、状态、研究索引、日志、机制、测试 | 未授权敏感资料、本地缓存、私人授权、大型原始产物 | 本轮结果会影响下次接手时，commit/push/readback |
| 本地执行目录 | 当前机器上的运行现场、临时产物、工具环境、未提交实验 | 自动等同于正式事实 | 执行时验证；需要继承的结果回写 GitHub |
| Obsidian | 可迁移机制、判断路径、案例、反例、迁移模板 | 医疗项目当前动态事实 | 项目经验可抽象为跨项目机制时 |

## 新会话读取顺序

1. `AGENTS.md`。
2. 本文件。
3. `project_facts/00_项目身份.md`、`01_当前已确认事实.md`、`02_当前状态_project_state.yaml`、`03_当前未决策事项.md`。
4. `logs/latest.md` 与 `logs/current_target.md`。
5. 按任务类型读取本目录对应机制。

如果这些来源互相冲突，先用 `05_事实源裁决与No_Guess_Routing.md` 裁决；如果仍无法裁决，输出 blocked，不得融合成一个自信结论。

## 默认动作

| 输入信号 | 默认动作 |
| --- | --- |
| 用户提出方向、候选市场或“让 Codex 做” | 先过真实意图闸门，不直接执行 |
| 任务会改变长期状态 | 回读 GitHub main，再决定是否写入项目事实 |
| 任务涉及复杂执行 | 先补六层需求确认和 Implementation Design |
| 任务涉及外部资料 | 先做 source + date + scope + fact classification |
| 用户说“不对” | 触发 self_repair_audit，由系统自查 fault layer |
| Codex 说“做完了” | 触发 Completion Relay Gate，不直接写 completed |

## 停止线

- 项目战略未锁定时，任何市场、产品、价格、验证顺序和 Go/No-Go 都保持 pending_decision。
- 医疗、法律、旅行、支付、隐私和外部联络默认不由 AI 直接决定。
- 研究报告、Perplexity、Web、聊天记忆和 Project 静态包不能覆盖 GitHub main 当前事实。
- 只有技术验证、没有内容/人工/业务证据时，不得跨层升级。
- Project 包生成不等于用户已上传，用户上传不等于 GitHub 动态事实改变。

## 医疗项目现实示例

用户说“我觉得先做美国市场”，这只是候选输入。ChatGPT 应先判断：这是用户正式拍板，还是让系统比较候选？当前要验证 Demand、Supply、支付能力、渠道触达，还是合规风险？只有进入正式决策记录后，GitHub 才能把它写成项目事实。
