# 事实源裁决与 No-Guess Routing

## P0 / P1 / P2

1. P0：用户本轮明确输入、禁止项和更正。
2. P1：GitHub main 的项目事实、真实执行证据、状态和日志。
3. P2：研究基线、Project 静态包、外部研究、聊天记忆、历史档案和跨项目机制。

冲突按 P0 > P1 > P2 处理。P0 指导本轮；要成为长期事实仍须回写 GitHub main。P2 只提供候选和方法，不得升级为 P1。

## No-Guess

Codex 不能猜战略、业务主体、价格、市场、客户、临床/法律结论、外部授权或完成态。ChatGPT 不得把研究摘要、Project 静态包或聊天记忆当作动态项目事实。

## 研究进入事实的路径

外部或基线研究 → 来源/日期/范围 → FACT candidate、INFERRED 或 HYPOTHESIS → ChatGPT 判断 → 如改变长期项目再由有权主体锁定 → 写入 project_facts 与 decision record。

当前研究基线的全部业务建议默认只属于 research_candidate，直到正式决策记录产生。
