# 失败反馈与 Self Repair Audit

触发条件包括：用户说“不对”、事实冲突、验证失败、同步失败、范围漂移或完成态被质疑。

## 诊断顺序

1. 目标：是否误解真实意图。
2. 事实：是否把研究、记忆或静态包当成 current fact。
3. 机制：权限、路由、状态规则是否冲突。
4. Implementation Design：路线、输入、fallback、能力边界是否缺失。
5. 执行：是否按允许范围和已锁定设计完成。
6. 验收：是否把技术/内容/人工/业务混写。
7. 同步：Git、日志、事实或 Package 是否落后。

输出必须给出已确认问题、待验证问题、最小修复范围、需要用户选择的事项和回归检查。不得要求用户诊断系统内部哪条规则坏了。
