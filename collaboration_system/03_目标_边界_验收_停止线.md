# 目标、边界、验收与停止线

## 解决什么问题

本机制把“我想做某件事”变成最小任务合同，防止执行阶段发生三种偷换：目标变大、边界变宽、验收变低。它尤其适合医疗项目，因为一个看似普通的执行请求可能牵涉患者资料、外部联络、医疗专业判断或合规承诺。

## 什么时候触发

- 任务要写文件、改仓库、生成同步包、整理研究或下发 Codex。
- 用户给出方向，但没有明确本轮交付。
- 任务涉及外部资料、真实机构、真实客户、价格、合作或敏感数据。
- 需要报告 completed、blocked、partial 或 pending。

## 输入

| 字段 | 要回答 |
| --- | --- |
| Goal | 本轮真正要证明、改变或交付什么 |
| Context | 当前事实、研究输入、上轮结果和限制是什么 |
| Locked Anchors | 哪些目标、范围、事实、验收、责任已经锁定 |
| Boundary | 允许和禁止的文件、工具、外部动作、数据类型 |
| Acceptance | 技术、内容、人工、业务、同步分别怎样判断 |
| Stop line | 什么出现就停止、回退、blocked 或请用户决定 |
| Blocked if | 缺哪些输入、权限或证据不能继续 |

## 判断流程

1. 写清本轮目标和本轮不做什么。
2. 标注事实来源：已确认、部分成立、待验证、推测、研究候选。
3. 把技术验收、内容验收、人感/人工验收、业务验收和同步验收分开。
4. 写出不可越过的停止线。
5. 只有合同完整，才进入 Implementation Design 或 Codex 执行。

## 角色和权限

用户锁定目标、红线、外部授权和最终验收。ChatGPT 把目标翻译成可执行合同并复审是否跑偏。Codex 按合同执行，缺合同字段时 blocked，不把缺口补成自己的判断。

## 医疗项目停止线

- 任何临床建议、治疗决定、用药、疗效承诺、医院名额保证、医疗签证保证、法律结论都需要专业主体。
- 任何外部联系、收款、签约、发布、创建患者记录、处理病历/证件/支付信息都需要用户明确授权。
- 未锁定战略时，不得把候选市场、候选产品、候选价格或候选验证顺序写成正式事实。

## Done When

任务合同完成时，应能让另一个新 ChatGPT 或 Codex 回答：

- 本轮要交付什么。
- 什么不属于本轮。
- 哪些证据足以证明完成。
- 哪些证据不能证明完成。
- 如果失败，应回哪一层。

## 用户怎么观察是否跑偏

看到 AI 说“完成了”时，问它完成的是哪一层：本地文件、测试、远端同步、内容验收、人工复审还是业务结果。回答不清就没有过本机制。

## 现实示例

如果以后要验证需求，不能只写“去找美国客户”。必须先写清：目标是验证支付意愿、问题严重性、转诊路径还是信任障碍；是否收钱；是否允许外联；成功证据是合格访谈、预约意向、订金、书面反馈还是只是“感兴趣”。
