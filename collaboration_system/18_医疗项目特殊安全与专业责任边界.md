# 医疗项目特殊安全与专业责任边界

## 解决什么问题

本项目涉及医疗、旅行、跨境服务、支付、隐私和机构合作。协作机制必须明确：ChatGPT 和 Codex 可以帮助整理、判断、设计和执行已授权的文件任务，但不提供诊断、治疗、法律结论或外部承诺。

## 什么时候触发

- 涉及患者、健康信息、病历、证件、支付、身份、医院、医生、治疗、用药、疗效、签证、保险、退款、合规、合同。
- 任务要求联系医院、联系客户、发送材料、收款、签约、发布或建立患者记录。
- 外部研究涉及医疗法规、医院资质、服务价格、临床结论或跨境旅行责任。

## 禁止事项

项目方、ChatGPT 或 Codex 不得提供：

- 诊断、治疗决定、用药建议、疗效/治愈承诺。
- 医疗签证保证、医院名额保证、医生可用性保证。
- 法律、税务、保险或支付合规结论。
- 未授权外部联系、收款、签约、发布。
- 在 Git、Project、普通聊天或日志中保存患者身份、健康信息、病历、证件、支付信息、密钥或私人授权。

## 默认动作

| 输入 | 默认处理 |
| --- | --- |
| 医疗/法律/支付问题 | 标为需专业主体复核 |
| 患者/个人健康资料 | 不写入仓库或 Project；提示需要合规系统和授权 |
| 医院/机构合作 | 未授权时仅做公开资料候选，不外联 |
| 价格/套餐/治疗结果 | 标来源、范围和待核验，不作为承诺 |
| 紧急或临床问题 | 引导用户联系当地紧急服务或合格医疗专业人士 |

## 角色和权限

用户决定是否授权外部动作、预算、主体、合作策略和最终商业拍板。ChatGPT 识别风险、列出需专业复核事项和停止条件。Codex 只能整理资料、写模板、跑验证和记录边界。专业主体承担医疗、法律、旅行、支付等专业判断。

## Blocked 条件

- 任务要求处理患者/个人健康信息但没有合规系统和授权。
- 任务要求对外联系、收款、签约或发布但未授权。
- 任务要求给出临床、法律或合规结论。
- 资料来源无法验证，却可能影响真实客户或医疗安全。

## 医疗项目现实示例

“帮我写客户问诊表”不能直接执行为患者记录系统。正确做法是：先判断用途是访谈、需求调研还是医疗预审；是否收集可识别健康信息；是否需要医生/律师复核；哪些字段不能进入 Git/Project；未授权前只能做低敏、非临床、非诊断的草案，并标明不得对外使用。

## 常见误用 / 反例

- 把公开医院网页写成合作确认。
- 把服务流程模板写成合法合规已确认。
- 把用户故事当患者资料保存。
- 把 AI 的风险清单写成专业意见。
