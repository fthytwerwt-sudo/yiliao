# 执行入口

本目录把项目判断转成可执行、可验证、可回写的任务。它不授权任何人绕过医疗、法律、数据、旅行或商业决策边界。

## 每次工作开始

1. 按 AGENTS.md 的新会话顺序回读动态事实。
2. 确认当前分支、工作区状态和待修改路径。
3. 写出 route_decision：任务类型、责任层、允许修改、禁止路径、阻断条件。
4. 选择一个与 logs/current_target.md 一致的唯一下一动作。
5. 在有证据后更新 facts、review 或 logs；不要只在聊天中宣布状态变化。

## 每次工作结束

1. 检查输出是否含真实、匿名化、可复现证据，而非预测或空字段。
2. 分别说明技术、内容、人工和业务完成态。
3. 运行比例合适的格式、链接、YAML、数据口径或文件完整性检查。
4. 需要长期保留时，更新日志和当前事实。
5. Git 收尾必须遵守 execution_rules/04_Codex执行验证与Git收尾.md。

## 路由模板

在任务说明或日志中使用以下字段：

| 字段 | 要填写的内容 |
| --- | --- |
| project_route | 对应项目层：facts、research、operations、review 或 mechanism |
| task_type | 例如供应商核验、客户访谈、外部研究、价格模型、文件修订 |
| responsibility_layer | 用户、ChatGPT、Codex、医院/机构、旅行伙伴、律师/专业方 |
| allowed_changes | 本次可以改的文件/事实类型 |
| forbidden_paths | 患者资料、密钥、原始报告、无授权外发等 |
| blocked_if | 缺事实、缺权限、需专业结论或会导致范围跳跃时 |
| evidence_needed | 什么输出才能支持本次判断 |
| completion_levels | 技术、内容、人工、业务四层状态 |

若一个任务无法填写这些字段，先不执行。
