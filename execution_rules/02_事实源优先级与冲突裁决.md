# 事实源优先级与冲突裁决

## 裁决顺序

1. GitHub main 的 project_facts 和 canonical state。
2. 可核验的真实执行、合同、报价、交易、履约、事故、专业书面意见。
3. latest/current_target 等同一仓库内的近期日志。
4. 用户本轮明确决定。
5. v3 基础市场报告。
6. 早期基础市场报告。
7. 外部研究与工具输出。
8. ChatGPT Project 静态包。
9. 聊天记忆和旧归档。

若较低层资料与较高层资料冲突，不能直接覆盖。必须记录冲突、来源日期、证据等级、影响范围和拟议变更，再由拥有权限的主体裁决。

## 版本裁决

- v3 是当前业务基线。
- 早期报告只能作为历史研究和补充素材。
- 若两份报告在首发市场、产品、价格、策略、合规边界或 90 天闸门上冲突，默认 v3 胜出。
- 用户明确后续新决定或新的可信现实证据可以改变 v3，但必须回写 current facts、state、日志和必要的静态包。

## 新证据进入项目的最低记录

| 字段 | 说明 |
| --- | --- |
| source_id | 可定位的来源/文件/联系人记录，不在 Git 存敏感正文 |
| source_type | FACT-A、FACT-B、FACT-C、INFERRED 或 HYPOTHESIS |
| observed_at | 原始资料或事件日期 |
| checked_at | 本项目核验日期 |
| scope | 适用国家、机构、SKU、客户群或时间窗口 |
| claim | 不夸张的原始主张 |
| limitation | 缺口、过期风险、样本限制、授权状态 |
| proposed_effect | 仅线索、改变假设、请求 DECISION 或可更新 fact |
| reviewer | 负责复审的角色 |

没有这些字段的新研究不得改写 current facts。
