# 脚本目录说明

当前阶段不放任何业务自动化脚本。

原因：项目尚未取得重复、稳定、合规的数据流和工作量证据；现在开发 CRM、RAG、自动化营销、支付、患者管理或多 Agent runtime 会制造重系统假象并扩大医疗/隐私风险。

本轮仅加入标准库回归测试，用于审计协作机制边界；它不接触患者、机构、客户、支付或外部服务。

未来只有在以下条件同时满足时才考虑新增业务脚本：

1. 有重复发生、人工记录已暴露瓶颈的任务。
2. 输入、输出、权限和失败模式已经明确。
3. 不处理患者身份或健康资料，或已有经批准的合规系统与专业结论。
4. 用户明确批准范围、可见性和外部动作。
5. 有可验证的测试/审计方案。

任何新脚本都必须先遵守 AGENTS.md、execution_rules/04 和 project_facts/07。
